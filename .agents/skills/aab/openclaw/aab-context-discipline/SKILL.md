# Context Discipline

## 核心原则

Agent 的输出质量 = f（上下文相关性，不是上下文数量）。
**更多上下文 ≠ 更好输出。** 无关信息会稀释注意力。
## Context Budget Levels（上下文预算三档）
每次任务开始前，自动判断应该用哪一档。默认从最低档开始。
### Level 1: Tiny（微型上下文）
用于简单 UI / 文字 / 样式改动。
```
最多读取：1-2 个文件
不触发：全局搜索、完整测试套件、项目结构探索
信号：用户说"改一个"换个颜色"把这个字改成..."
```

### Level 2: Normal（标准上下文）
用于正常功能开发、中等改动。
```
最多读取：3-5 个文件
允许：针对性搜索、运行相关验证
不触发：全项目扫描、读取不相关模块
信号：用户说"加一个功能"做一个页面"对接一个..."
```

### Level 3: Heavy（完整上下文）
仅当用户明确要求时才用。
```
最多读取：不限（但先列计划再读）
必须：读完先总结发现再开始改
触发条件：用户明确说"全面检查"重构整个项目"审计"
不要自己升级到 Heavy——除非用户要求。
```

选择逻辑：**默认 Tiny → 不够用升 Normal → 用户要求才 Heavy。不上来就全量加载。**

## AAB 项目类型与上下文策略

### 单文件 HTML 项目（最高频）
```
上下文需求：极简
加载内容：
  - 当前 HTML 文件（或相关片段）
  - aab-frontend-ui 的配色/风格引用（如果涉及 UI）
  - 用户刚说的需求
不需要：
  - 项目结构探索
  - 依赖分析
  - 多文件追踪
```

### 比赛 Demo 项目

```
上下文需求：中等
加载内容：
  - 项目方案/需求文档（相关段落，非全文）
  - 当前工作文件
  - aab-competition-demo 的六步方法论
  - 比赛约束（时间、展示形式、评委关注点）
不需要：
  - 完整的项目书
  - 历史版本对比
  - 过多的技术调研
```

### 桌面/Electron 项目

```
上下文需求：中等
加载内容：
  - 当前模块代码
  - 相关 Electron API 文档
  - 项目已有的 pattern（找 1 个类似实现参考）
不需要：
  - 整个 Electron 文档
  - 所有 IPC 通道列表
```

## 会话管理

### 新会话启动
不用每次都重新探索。快速注入：

```
项目：[名称]
类型：[单文件 HTML / 比赛 Demo / Electron / 其他]
当前阶段：[刚开始 / 进行中 / 收尾]
上次做到：[一句话描述]
关键文件：[1-3 个文件路径]
风格约束：[暗色科技风 / 无特殊要求]
```

这个模板覆盖 90% 的场景，不需要更复杂的结构。
### 任务切换

切换任务时：
1. **判断相关性**：新任务和当前上下文有关吗？
   - 有关 → 保留上下文，只补充新信息
   - 无关 → 告诉用户"建议开新会话"，或主动总结当前进度后切换
2. **不要混在一起**：比赛项目和桌面项目的上下文不要共存

### 上下文过长时

主动发现并处理：
- 对话超过 30 轮 → 主动总结一次进度
- 引用了 10 轮前的代码 → 那个代码可能已经改了，重新读
- 用户开始重复说同一件事 → 你的上下文可能已经满了，总结后继续

## 规则文件策略

### CLAUDE.md（Claude Code）
aab 的项目不需要厚重的 CLAUDE.md。最小模板：

```markdown
# [项目名]

## 技术栈
[一行]

## 启动命令
[一行]

## 关键约束
- [1-3 条，不要多]
```

**不要写的内容**：
- 代码规范（Agent 会看现有代码自己学）
- 目录结构说明（Agent 能自己看）
- 长篇架构描述（需要时口头说就行）

### AGENTS.md（Codex）
同理，保持最小。Codex 的上下文窗口更敏感，内容越少越好。
### 什么时候值得写规则文件
- 项目超过 3 个文件 → 写
- 有非标准启动命令 → 写
- 有特殊约束（如 不能引入外部依赖）→ 写
- 单文件 HTML → 不写，口头说就行

## 跨平台上下文迁移

在 Claude Code 和 Codex 之间切换时：

```
Claude Code 用的上下文 → 提炼为 3-5 句话 → 喂给 Codex
不需要：
  - 完整的对话历史
  - Claude 特有的工具调用记录
  - 中间探索过程
```

反过来同理。**跨平台只传递"决策"和"当前状态"，不传递"过程"。**

## 反模式
| 反模式 | 改正 |
|--------|------|
| 每次会话都重新探索项目结构 | 记住上次的结论，直接开始 |
| CLAUDE.md 写成技术文档 | 保持最小，只写 Agent 需要知道的 |
| 把整个方案书喂给 Agent | 只喂当前任务相关的段落 |
| 上下文混在一起不清理 | 切换任务时主动总结/清理 |
| 把 Claude Code 的对话原样搬给 Codex | 提炼后再传 |
