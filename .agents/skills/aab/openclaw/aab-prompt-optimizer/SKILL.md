# Prompt Optimizer

## 核心原则

好的 Prompt 不是越长越好。三个维度评估：

```
精确度：Agent 做事是否符合预期
Token 成本：Prompt 本身消耗多少 token
鲁棒性：换一个场景/项目，Prompt 是否仍然有效
```

## Prompt 结构模板

AAB 标准 Prompt 四段式：

```
[角色] 你是谁（1 句话）
[任务] 做什么（3-5 句话，只写关键约束）
[风格] 怎么做（如果有 UI 相关要求）
[输出] 产什么（格式要求，如果有）
```

示例：
```
角色：你是前端开发，擅长暗色科技风 UI。
任务：把以下数据做成 Dashboard 页面。
  - 包含 4 个指标卡片和 1 个趋势图
  - 单文件 HTML，零依赖
  - 数据硬编码在 JS 里
风格：暗色科技风，参考 aab-frontend-ui 配色。
输出：直接给完整 HTML 文件。
```

## 压缩技巧
### 删掉这些

```
✗"请帮我..." → 不需要礼貌用语，直接说
✗"你应该..." / "你需要..." → 不需要指导 Agent 怎么思考
✗"记住..." / "不要忘记..." → 如果会忘，说明 Prompt 没写清楚
✗ 背景故事 → 除非影响决策，否则不写
✗"如果还有其他问题请告诉我" → 废话
```

### 用这些替换
```
✗"请仔细检查代码，确保没有 bug，并且代码风格符合项目规范"
✓"检查：无报错、风格一致"

✗"你需要先分析需求，然后设计架构，再开始编码"
✓"先给方案，确认后写代码"（如果确实需要分步）
```

### 压缩率目标
```
你的原始 Prompt → 压缩到 40-60% 长度 → 不损失精确度
```

如果压缩后 Agent 行为变了 → 说明原始 Prompt 里有废话。
## 跨平台适配

同一个任务，不同平台的 Prompt 写法不同：
### Claude Code

```
直接说任务，可以简短
Claude 擅长理解上下文，不需要过度解释
例："在 index.html 里加一个数据看板区域"
```

### Codex

```
需要更明确的指令
Codex 的自主探索倾向更强，需要加边界约束
例："在 index.html 的 <main> 标签内添加数据看板。不要修改其他部分。不要引入外部依赖。"
```

### Gemini CLI

```
需要更结构化的输出要求
Gemini 有时输出太长，需要限制
例："添加数据看板到 index.html。只输出修改后的 <main> 部分代码，不要全文。"
```

### Antigravity

```
类似 Claude Code，但需要更多上下文引用
Antigravity 对文件路径敏感
例："修改 src/pages/dashboard.html，添加指标卡片区域"
```

## 调试 Prompt

当 Agent 输出不如预期时，按这个顺序排查：

```
1. Prompt 里有歧义吗？
   → 同一个句子能读成两种意思 → 改写

2. Prompt 里缺信息吗？
   → Agent 做了一个你不想要的东西 → 补充约束

3. Prompt 里信息太多了吗？
   → Agent 忽略了关键要求 → 删掉次要信息

4. 是 Agent 自身的问题吗？
   → 换个平台试试同样的 Prompt
```

## 常用 Prompt 片段

可以直接复用的模板：

```
# 快速改样式
"把[元素]的颜色改成[颜色]，字号改成[大小]，间距改成[值]。不改其他。

# 快速加功能
"在[位置]添加[功能]。要求：单文件 HTML、零依赖、暗色科技风。

# 快速检查
"检查这个页面：控制台报错、文字溢出、移动端显示。只报告问题，不改代码。

# 比赛材料生成
"基于这个 Demo，生成一段 200 字的项目简介。突出：创新点、技术路线、应用价值。
```
